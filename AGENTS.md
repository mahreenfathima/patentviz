# Patent Viz: playbook for coding agents

The normal path is `npm start` (or `node cli/patentviz.js`). It runs the whole flow: SerpApi search, script, voiceover, scene data, `video.html`, and the optional MP4 and PDF. Use this file only when you work on the project by hand or drive it from an agent such as Claude Code or Gemini CLI.

## Rules

- **Light theme and 16:9 only.** The CLI produces this. Do not add other themes or aspects without asking.
- **Write only inside `projects/<slug>/`** when generating or editing a patent's files.
- **Do not edit `engine/index.html`** unless the user asks for an engine change. Every project depends on it.
- **Do not edit `cli/patentviz.js`** unless the user asks for a code change.
- **Never commit or print `.env`.** It holds live API keys.
- **Render only when asked.** MP4 and PDF export are slow and use Chromium and ffmpeg. Run them only when the user requests them.
- **Every fact on screen must come from `projects/<slug>/source.json`**, which is saved from SerpApi. Do not add claims from memory.

## Project layout

```
cli/patentviz.js      main CLI
cli/export.py         video.html -> projects/<slug>/export/<slug>-16x9.mp4
cli/pdf.py            infographic.html -> projects/<slug>/<slug>-infographic.pdf
cli/cutout.py         background cut-out for drawings and photos
engine/index.html     shared animation engine (GSAP timeline)
engine/vendor/        gsap.min.js, inlined into each video.html
projects/<slug>/      one patent's generated files
```

## Steps for a manual run

1. Confirm `.env` has `SERPAPI_API_KEY`, `GEMINI_API_KEY` and `GROQ_API_KEY`. Do not print their values.
2. Ask the user for the patent number or keyword, the focus (How it works / Why it matters / Who made it / Balanced), whether they want a voiceover, and the colour preset.
3. Run `node cli/patentviz.js` and answer its prompts, or let the user run it.
4. Check `projects/<slug>/`. It should contain `video.html`, `project.js`, `source.json`, `infographic.html` and `voice/voiceover.wav`.
5. If the user asks for a fix to the video, edit `projects/<slug>/project.js` and reload `video.html`. Keep the `window.PROJECT = {...}` shape. Do not rewrite the file from scratch.
6. If the user asks for an MP4 or PDF, run the matching command from the project root:

   ```bash
   python3 cli/export.py <slug> --aspect 16x9 --fps 30
   python3 cli/pdf.py projects/<slug>/infographic.html projects/<slug>/<slug>-infographic.pdf
   ```

## Opening and checking the video

`projects/<slug>/video.html` is self-contained. GSAP is inlined, so it opens directly in a browser with no server. Do not start an HTTP server for it.

The page sets these on `window`:

| Property | Meaning |
|---|---|
| `__ready` | `true` once the timeline is built |
| `__duration` | Length in seconds |
| `__size` | `[width, height]`, 1920x1080 for 16:9 |
| `__seek(t)` | Jumps the timeline to `t` seconds, deterministically |
| `__missing` | Assets the page could not load. It should be empty |
| `__hasAudio` | Whether the page has a voiceover |

To check a render frame by frame, wait for `__ready === true`, confirm `__missing` is empty, then call `__seek(i / fps)` for each frame. `export.py` does this for you.

## Notes

- The voiceover is `projects/<slug>/voice/voiceover.wav`. It is generated by Gemini TTS, and its timing follows the scenes.
- `export.py` is 16:9 by default. It also accepts `--aspect 9x16`, but the engine's 9:16 layout has not been tested with this project.
- Groq writes the infographic text. Gemini writes the narration and the drawing captions. Free-tier limits apply, so a run can fail with a 429 or 503 error. Wait and run again.
